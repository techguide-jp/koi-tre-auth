# 人物設定の管理画面

## 目的と画面

既存6人の会話用設定を `/admin/characters` で編集する。評価用の知識は従来の `/admin/knowledge` に分離し、`/admin` を入口にする。人物一覧から一人を選び、プロフィール、価値観・距離感、話し方、関係段階、場面別の反応、好感度リアクションの6フォームを切り替える。各フォームは独立した保存操作を持つ。名前・年齢・画像に対応する人物IDは既存カタログのまま使う。

フォームは短い項目へ分割し、場面の反応は方針と参考セリフを別々に入力する。会話例は固定台詞として繰り返さず、その人物の表現の参考にする。公開・動作確認・履歴は編集フォームと分ける。保存中の表示、二重送信防止、近くの成功・失敗表示、未保存変更の保護を設ける。

## 保存と公開

人物ごとに下書き・リビジョン・現在の公開版を持ち、公開内容は不変の履歴へ保存する。公開は同じリビジョンの返信確認と管理者の確認後に行う。旧版への復帰は人物ごとに行い、別人物の設定を変更しない。全APIで既存UID許可リストを検証する。

加算的migrationで `character_policy_settings`、`character_policy_releases` と練習の `character_context` を追加する。新しい練習は公開版、未公開なら既存人物設定から作る初期版を開始時に保存する。再送・再開・言い直しはこのスナップショットを使い、開始済み練習へ最新の下書きや公開版を混ぜない。既存練習は従来どおりとする。

## 返信への反映

人物のプロフィール、価値観、話し方と、その話の関係段階、現在の場面に合う反応例を `partnerDescription` に組み立てる。既存Dify Workflowが参照する入力を使い、Difyの新しいアプリ・課金・Workflow移行を必要としない。上位の共通方針・場面・双方の意思・正確な事実を優先する。

Jevによる25点評価は元の場面と評価方針で実施し、人物の好みや話し方を新しい採点条件にしない。好感度の結果セリフは練習開始時に保存した人物設定から選ぶ。ブラウザへは結果セリフだけを返し、人物設定全文を公開しない。

入力全体の上限を守るため、各項目は短い上限を持つ。関係段階はその話に対応する一段階だけ、反応例は場面と発言に合う少数だけを使う。既存の4000字制限を超える場合は、古い会話の記憶と補助例を先に減らし、人物の基本設定や現在の場面を黙って切り捨てない。

## 検証・公開

管理APIの401/403、各フォームの入力検証、保存競合、人物別の独立、同じ下書きの確認・公開、他人物の版への切替拒否、公開版の不変性を検証する。生成入力とJev入力の分離、3/6往復・再開・言い直しの版固定、過去の話への再練習、結果セリフ、入力上限を確認する。PGliteで全migrationと既存回帰テストを実行し、再generate差分なし、型・lint・ビルド、PC・スマホの画面と保存操作を確認する。

本番課金は停止を維持する。本番DB・アプリの追加反映は、変更内容の検証後に既存の公開手順へ載せる。

# 第1話をログインせず体験する

## 体験と引き継ぎ

全6人の第1話を、人物ごとに一度、3往復で体験できる。通常と同じ公開人物設定・評価方針・Dify/Jevを使い、表情、25点評価、星形グラフ、具体的な振り返りを表示する。第2話以降、6往復、共通・カスタム場面はログイン後に利用する。

体験後はGoogleログインで会話・評価・XP・カード・クリア判定を引き継ぐ。体験中にはアカウントの枠を消費せず、引き継ぎで最初の返答を保存するときに通常の月枠を1枠使う。再送・再読み込み・再ログインで二重消費しない。枠不足時も体験記録を残し、30日間の保存期間内に枠が利用可能になれば、同じアカウントで引き継げる。評価待ちは0点にせず、引き継ぎ後に既存の無料再評価を利用する。

## 保存と制限

- 既存アカウントとは分けたguest_sessions・guest_practices・guest_rate_limitsを加算的migrationで追加する。スキーマから生成し、既存テーブルと人物の公開内容を変更しない。
- 256bitのランダムトークンをHttpOnly・SameSite=Lax・本番SecureのCookieへ保存する。DBにはトークンのSHA-256だけを持つ。別Cookieからの読み取り・送信・引き継ぎを拒否する。
- 体験は30日間保持し、期限切れは開始時に件数を絞って削除する。Cookieを失うと引き継げないことを案内する。引き継ぎ済みの通常会話は削除しない。
- 同じCookie・人物は同じ会話を再開する。第1話・3往復の制限は開始APIと送信処理の両方で検証する。人物設定と評価方針は開始時に固定し、全文をブラウザへ返さない。
- IPはフレームワークのgetClientAddressから取得し、日付を含むHMACにして保存する。日ごとの開始はIPあたり12件・全体300件、生成はIPあたり60回・全体1200回まで。会話ごとの生成試行は最大9回。新しいインフラや秘密鍵は追加せず、既存サーバー秘密値をHMACに利用する。
- POSTは同一Originを要求する。生成リース、練習ID・送信ID、DB行ロックで重複生成と古い処理の上書きを防ぐ。失敗した返答は同じ内容で再試行できる。

## 既存処理との接続

公開APIはゲスト専用にし、既存の/api/meは認証必須を維持する。ゲストの会話は通常の生成アダプターを呼ぶ。引き継ぎ先はFirebaseで確認した本人に一度だけ固定し、サーバー保存済みの返答を既存の予約・保存処理へ渡す。AIを再生成せず、利用枠・XP・好感度・クリア判定を既存ルールで一度だけ確定する。開始時スナップショットも引き継ぐ。

ホームの人物選択に未ログイン用の第1話開始導線を出す。会話画面はゲスト専用APIで読み込み・送信し、完了時にログインと引き継ぎを案内する。ログイン後は同じ練習IDの通常画面へ移り、第2話や既存の再評価・アルバムを利用できる。

## 実装・検証の順序

1. schema、ゲスト保存、Cookie・Origin・生成回数制限、通常生成との接続を実装する。
2. ゲスト開始・読み取り・送信と認証済み引き継ぎAPIを追加し、既存保存処理へつなぐ。
3. ホーム・会話・結果・ログインの導線を接続する。
4. 独立PGliteで全migration、所有権、直接POST、再送・並行処理、生成失敗、評価待ち、期限、枠不足、引き継ぎ時の一度だけの消費・進行を検証する。
5. 型・lint・全回帰テスト・ビルド・migration再生成差分なし、PC/スマホの未ログイン開始からログイン後の継続まで確認する。
6. PRレビューとCIを確認し、本番への追加反映時はmigrationを先行する。課金の設定は変更せず、Productionの販売停止を維持する。

# 評価方針と知識の運用

## 編集する場所

Koi-Treのマイページにある「運営管理：評価方針と知識」から `/admin/knowledge` を開く。管理APIはFirebaseトークンとサーバーのUID許可リストで認証・認可する。運営者として指定されたGoogleアカウントだけを登録し、メールアドレスの自己申告で権限を付けない。初期権限は `y.takahashi@techguide.jp` のみ。

1. **基本方針**：毎回読み込む価値観・判断の方針。20〜3,000字。
2. **知識文書**：場面別ノウハウ・例・研究メモ。タイトル、本文、対象場面を編集する。40文書、本文は各12,000字、全体10万字まで。研究メモには出典と適用限界も記載する。
3. **下書き保存**：練習へはまだ反映しない。別画面と競合したら最新版を読み直す。読み直す前に未保存の内容があれば退避する。
4. **動作確認**：8種類の架空会話から、変更した場面を選んで実行する。取得した資料、返答、Jev評価、分析・言い換えを確認する。AIの利用は発生するが、通常の練習枠・XP・好感度は変わらない。
5. **公開**：保存した同じ内容で確認が成功し、管理者が結果を確認してから公開する。接続・評価の成功は助言の正しさを保証しない。意図を保つ言い換え、断りの尊重、場面に合う助言を人が確認する。

下書きを変更したら動作確認をやり直す。確認結果は内容のハッシュ・下書きの版・実行した管理者と結び付け、画面から成功フラグを送るだけでは公開できない。

## RAGの範囲

Koi-Treが公開版から関連箇所を取得し、**同じ基本方針と資料をJevとDifyへ渡す**。Difyのナレッジ画面を別に更新する必要はない。基本方針は検索結果にかかわらず毎回含める。

初期の検索方式 `scene-bm25-v1` は場面タグと日本語の2文字単位を扱うBM25。対象外の場面を除き、タイトル・本文の一致から最大3箇所、同じ文書から最大2箇所、各600字以内を選ぶ。意味の近さを埋め込みで検索する方式ではないため、同義語や関連語を文書へ含め、該当する場面タグを付ける。タグなしの文書は全場面で検索候補となるが、本文等の一致がない場合は取得しない。

外部ベクトルDB・埋め込みAPI・Dify Datasetを追加しない構成。検索自体の外部API呼び出しは増えない。渡す資料によってモデルの入力トークンと処理時間は増える。

固定のJSON形式、本人の引用・事実・意思の検証、同意の尊重、料金・利用枠・合格点は管理文書で変更しない。資料は会話の発言ではなく参考情報として扱う。

## 公開版と過去の会話

公開版の内容は変更せず、次回公開時に新しい版を作る。練習を作成した時点で版を固定し、3/6往復、途中再開、再送、同じ会話内の言い直し、無料再評価でも同じ版を使う。別の練習として始め直す場合は、その作成時点の公開版を使う。各生成の版・検索方式・参照文書と箇所・文脈ハッシュを記録する。無料再評価では元の箇所を復元する。

導入前の練習は従来方針として扱う。方針更新によって過去の点数・好感度・クリアを再計算しない。公開履歴の「v○へ戻す」は、新しく作る練習だけを旧版へ戻す。直近30版を画面に表示し、古い版もDBから削除しない。

## 導入・切り戻し

- 加算的migration `0007`：公開版、下書き設定、練習の版ID、各返答の参照記録を追加する。既存会話を更新・削除しない。
- Dify Workflowへ任意の `policy_context` と `policy_hash` を追加し、出力で `policy_hash` を返す。未指定の従来入力も動作させる。アプリは受領値を照合し、旧Workflowが方針入力を無視したときは保存・消費を成功させない。
- `KOITRE_ADMIN_UIDS` はサーバー専用。`KNOWLEDGE_POLICY_ENABLED=true` かつ公開版があると、新規練習へ版を割り当てる。
- 導入順はDifyの互換確認・公開、DB migration、対応アプリと許可リスト、架空会話の確認、初期方針公開。販売停止 `BILLING_ENABLED=false` は継続する。
- 不適切な助言が出たら管理画面で確認済みの旧版へ戻す。新規割当を止める場合はフラグをfalseへ変更して再デプロイする。開始済みの練習が参照する版やDB列は削除しない。

実装の設計は [管理画面とRAGの計画](knowledge-policy-admin-plan.md)、初期の価値観は [評価・アドバイスの基本方針](evaluation-principles.md) を参照する。

# キャラクターと進める会話の練習

> 2026-11-09整理：以下は3話×6人で始めた初期設計・検証の記録。現行は[6人×12話・料金と再練習](routes-and-billing.md)、[合格点と好感度](stage-affinity-progression.md)へ拡張し、PR #24まで公開済み。判断軸は[評価・アドバイスの基本方針](evaluation-principles.md)、全体の状態は[文書一覧](README.md)を参照。

## 承認された体験

話したい相手を男性・女性から選び、その側の成人キャラクター3人をバストアップで表示する。キャラクター固有の3話×6人と共通6場面、計24場面を用意する。各人物に性格・好み・話し方を持たせ、6表情を会話の文脈に合わせて切り替える。3往復・6往復、場面選択・おまかせ、エピソードの続き、振り返り、同じ練習内1回の言い直しを提供する。

ゲーム要素は完了20XP、根拠付きのミッション達成10XP、100XPごとのレベル、次の話の解放、挑戦のバッジ、思い出アルバムとお気に入りのひと言。レベルは練習経験を表す。表情や物語は、本人と相手の意思・断りを尊重し、会話の内容に合わせる。

## 保存と互換性

- 既存の認証、利用枠（月10回）、生成予約、3往復の過去履歴を維持する。新しいキャラクター練習はセッションごとに3/6往復を保存する。場面の閲覧や引き直しは利用枠を消費しない。
- practicesにadventure（人物・場面・往復数）、reward（確定XPとミッション根拠）、favorite_turn、rehearsal（1回の言い直し）を追加。practice_turnsにpresentation（表情・短いしぐさ）を追加する。すべてnullableで既存行の更新は不要。
- XP・バッジ・解放・アルバムは本人の完了履歴から求める。完了処理のトランザクションでrewardを一度だけ確定し、クライアントからXPを受け取らない。
- ミッションはサーバー定義。生成側が示す達成の引用が実際の本人の発言に一致するときだけ追加XPを付ける。引用不正や補助情報欠落では通常の会話と完了XPを継続する。
- エピソードの解放はUIだけでなく作成時も検査する。会話の再送・別ユーザーアクセス・完了後の追加送信は既存の保護を維持する。
- 言い直しは完了済みの本人のキャラクター練習に限定し、既存の予約期限・トークンで競合を防ぐ。成功は一度だけ保存し、追加XPや利用枠消費はない。元の会話と分析は残す。
- お気に入りは本人の完了済み発言の番号だけ保存する。取得・更新とも本人認証を必須とする。

## AI・画像

人物とエピソードをサーバーカタログから解決してDifyへ渡す。出力は既存のreply/feedbackに任意のpresentation・missionを追加。表情は許可リスト、しぐさは短い文章、ミッションの引用は実際の本人の発言で検証する。Jevの5観点と引用付き分析を維持し、初期設計の6往復分析は代表的な3返答の詳しい言い換えを返していた。現行のanalysis.version=3は全6返答を分析・保存する。途中の会話は採点を見せず、キャラクターとして反応する。

各人物の6表情と腕・手のポーズを一枚の画像として事前制作し、表示範囲を切り替える。自然体、手を開く、襟元に手を添える、あごに手を添える、手のひらを上に向ける、胸元に手を添える、の6種類。顔・服装・構図を固定する。毎回の画像生成は行わない。

## 実装・検証・公開の順序

1. カタログと型・DBの追加列、migrationを作成。
2. セッション作成・往復数・完了報酬・進行・言い直し・お気に入りの処理とテストを実装。
3. 性別選択→人物→物語の画面、会話中のバストアップ・表情、結果のXPと次の話、アルバムを実装。
4. Difyの既存入力を保ったプロンプトを更新し、架空会話で実生成と引用・表情・ミッションを検証。
5. DB統合テスト、再送・権限・不正入力・旧履歴、整形・型・ビルド、PC/モバイルの実操作を確認。
6. 追加列のmigrationを先に適用。Dify更新・CI確認・main反映・本番配信を別々に確認する。ロールバック時は追加列と保存済みデータを残す。従来の練習は旧版でも利用できるが、新しいキャラクター練習（特に6往復）の表示・再開には新版が必要なため、公開後の不具合は原則として修正版の配信で対応する。

## 検証結果

- 既存テストを含む12ファイル・134テストが成功。本人認証、エピソード解放、3/6往復、再送による報酬・利用枠の重複防止、100XPのレベル境界、ミッション引用検証、お気に入り、言い直しの競合・失敗後の再試行を確認。
- 独立したローカルPostgreSQL 17へ全migrationを適用。再度のgenerateで差分なし。Firebase Auth Emulatorと架空の応答を使った画面検証で、3往復と6往復の完了、途中再開、次話解放、XP、アルバム、お気に入り、言い直し1回をPCと390px幅で確認。掲載スクリーンショットの会話は検証用。
- 別途Difyの実モデル（gpt-6-luna）とJev（jev-1.14.0）で架空会話を検証。6往復では全体要約と1・3・6回目の詳しい分析、断る場面では意思を伝えた点の評価、従来の3往復では既存形式の分析を確認。気持ちを述べない返答ではミッション未達成となり、改善案が出た。全出力を実装と同じパーサーに通し、引用・表情・ミッションの整合を確認。
- 型チェックはエラー・警告0、整形・ESLint・本番ビルドが成功。公開ページのSEO検査とアルバムのnoindexを確認。

# 評価・アドバイスの基本方針

2026-11-09時点の設計書・Difyプロンプト・Jev基準・進行処理を整理した、判断軸の入口。今回の整理による採点・生成処理の変更はない。公開状況は [仕様・実装状況](README.md) を参照する。

## 大切にする価値観

Koi-Treは、自分の気持ちや希望を伝えながら、相手の意思も尊重してやり取りする練習を扱う。理解することと同意することを分け、自分を抑えて相手に合わせ続けることを正解にしない。

- **双方の意思を尊重する。** 誘う・断る・保留する・会話を終えるという選択を認める。短い明確な断りにも価値があり、謝罪・理由・代案は必須にしない。
- **今回の場面と発言を根拠にする。** 明記された関係、直前の相手の言葉、本人の目的を見て評価する。誰が話した内容かを区別し、本人が言っていない気持ち・好み・経験を補わない。
- **相互性と自然さを重視する。** 質問・回答・感想・自己開示・自然な終了を含む会話の受け渡しを見る。質問数、文字数、敬語、共通の趣味の有無だけでは採点しない。
- **改善は選択肢として提案する。** 本人の意図や持ち味を保ち、今回の状況で試せる具体的な言い方を示す。承諾と断りを入れ替えたり、好意や将来の約束を作ったりしない。
- **根拠と不確実さを示す。** 強み・改善点の水増しを避ける。短い会話で観察できる話し方を扱い、人格、相手の本心、脈あり、恋愛の成功率は判定しない。
- **練習の楽しさと本人の選択を両立させる。** 点数・好感度・キャラクターの反応は練習を続けるための仕組み。交際の成立や相手の同意を数値だけで確定しない。

## 判断軸を確認する順序

以下は設計・レビュー時に、評価と提案の一貫性を確かめる確認順。

1. **場面と目的を確かめる。** 初対面なのか、誘いなのか、自分の希望や断りを伝える場面なのか。関係段階が不明な部分を決めつけない。
2. **実際のやり取りを読む。** 3往復は全3返答、6往復は全6返答とそれぞれの直前の相手の発言を見る。最後の一言だけで総評を決めない。過去の記憶を今回の本人の発言として採点しない。
3. **5観点を場面に合わせて評価する。** 表面的な形式や相手役の都合で点数を決めず、その場面で意思や関心が伝わったかを見る。
4. **観察と根拠を対応させる。** よかった行動・工夫できる行動を、本人の発言番号と原文の引用に結びつける。既にできていることを不足扱いしない。
5. **目的の分かる言い換えを提案する。** 何を変えるとどう伝わりやすくなるかを短く説明する。自然に成立する場合だけ、別の目的の言い換えを添える。
6. **次に試す行動を一つ選ぶ。** 総評・根拠・言い換えと矛盾しない目標にする。目標を達成した会話では、そのよい行動を次も使う練習にできる。

## 5つの評価観点

各観点はJevの0〜5点、合計25点。0〜5の段階の文章は観点ごとに異なり、実際の定義は [Jevのルーブリック](../src/lib/server/jev-practice.ts) に置く。

| 観点           | 見ること                                                                                               |
| -------------- | ------------------------------------------------------------------------------------------------------ |
| 受け止め・共感 | 相手の話や明示された気持ち、直前の問いに合う応答か。質問への自然な回答も受け止めとして扱う。           |
| 自分の伝え方   | 好み・気持ち・考え・希望・断る意思が、場面に必要な深さで伝わるか。長さや深い告白を要求しない。         |
| キャッチボール | 相手の反応を踏まえ、話す・聞く・答える・終えるを無理なく選べるか。質問の数には置き換えない。           |
| 話題のつながり | 直前の話、相手の問い、場面の目的と自然につながっているか。成立した約束や断りの尊重による終了も含む。   |
| 距離感・配慮   | 本人と相手の意思、関係の深さ、都合に合う言い方か。決めつけ・侮辱・断りの無視・一方的な要求を区別する。 |

支払い・好感度を理由に採点を甘くしない。3往復と6往復のステージ合格基準は共通。合格点・配慮の最低点・次話の必要好感度は [12話のクリア条件](stage-affinity-progression.md) と [進行処理](../src/lib/adventure-progression.ts) に定義する。

## 場面に合わせる

| 場面         | 評価と助言の重点                                                                             |
| ------------ | -------------------------------------------------------------------------------------------- |
| 初対面       | 無理のない深さの好みや感じ方と、相手への関心。深い告白や誘いは必須にしない。                 |
| 趣味・休日   | 好きな点や感じ方を知り合えること。相手の問いに答える短い返答も認める。                       |
| 静かな時間   | 目の前の料理・雰囲気への感想や、落ち着いて過ごしたい意思。沈黙を失敗扱いしない。             |
| 誘い         | 一緒に過ごしたい希望と返答できる提案、相手の意思の尊重。誘いの成否を能力に換算しない。       |
| 断り・境界   | 自分の意思を伝えることと、相手の断りを受け入れること。承諾へ変えたり理由を追及したりしない。 |
| すれ違い     | 具体的な出来事、自分の気持ちや希望、異なる見方を聞く余地。一方的な譲歩や同意を正解にしない。 |
| 嬉しい出来事 | 相手にとって嬉しい点を具体的に受け止めること。話を自分の実績へ奪う助言をしない。             |
| 大切な気持ち | 好意・安心・迷い・希望を本人の言葉で伝えること。保留や時間がほしいという意思も尊重する。     |

AI相手が質問役に偏った場合も、その流れに沿って答えた利用者を機械的に不利にしない。詳細は [場面別方針](../src/lib/server/practice-coaching.ts) と [場面別設計・研究の参照先](scene-aware-coaching.md) に置く。

## 分析・改善提案の作り方

- 総評、強み、改善点、5観点の観察、各返答の言い換えと目的・理由、次の練習目標を扱う。
- 強み・改善点は根拠がある件数だけを出し、0件も認める。問題を薄めるための肯定や、件数を埋めるための欠点を作らない。
- 言い換えは本人の具体的な話題・事実・意思を保つ。相手が「静かな場所が好き」と話しても、本人もそう感じると推測して言い換えに加えない。
- 全返答に欠点を探す必要はない。よい返答には、持ち味を保った別の自然な表現を提案できる。
- 生成された分析・言い換えを検証して保存し、アプリの定型文で上書きしない。

Difyへ渡す指示は [Workflowのシステムプロンプト](../dify/koi-tre-practice.yml)、出力形式は [JSON Schema](../dify/practice-output.schema.json)、原文・発言番号の照合は [出力検証](../src/lib/server/practice-feedback.ts) にある。

## 不確実な評価の扱い

観察可能性と確信度を点数と分ける。一定の材料があり段階の迷いが隣接する範囲なら「参考値」、材料不足・評価の大きな分散・欠損はそれぞれ区別する。有効な5観点が揃った場合に合計を出し、旧採点や欠損を0点で補わない。

数値の参照元はサーバーが実際に取得したJevの出力。生成AIが自分で書いた採点結果は保存しない。Jevの結果だけに合わせて会話にない欠点を作らず、文章の観察には会話の証拠を優先する。Jev障害時も会話に基づく文章分析は継続できるが、攻略判定は評価待ちとし、保存済み会話を追加枠なしで再評価できる。有効な攻略評価の確定後は振り直さない。

判定の実装は [評価状態・合計](../src/lib/practice.ts)、[攻略判定](../src/lib/adventure-progression.ts)、[無料再評価](../src/lib/server/practice-assessment-service.ts) を参照する。

## AI相手と、好感度の演出

AI相手は具体的な反応と短い自己開示も返す。毎回の質問や言い直しを要求せず、会話を終える意思や境界を優先する。本人に必ず同意する相手にはせず、キャラクターの性格と場面に沿って反応する。再練習はその時点の関係を使い、未来の交際や未経験の出来事を思い出したふりをしない。

| 種類                         | 現行の作り方                                                                                                                                         |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 会話中の返答・表情・しぐさ   | Difyが会話と人物・場面の文脈から生成する。                                                                                                           |
| 会話の分析・改善案・言い換え | Difyの文章とJevの実評価を使い、原文等を検証して保存する。                                                                                            |
| 結果画面の好感度リアクション | 保存された実際の増減・評価・検証済み引用をもとに、キャラクター別・観点別の事前定義文と表情を選ぶ。会話固有のセリフを毎回生成する機能は追加改善候補。 |

好感度の低下に伴うネガティブ反応は、確かな配慮評価で実際に下がった場合に限る。不合格、増減0、評価待ち、丁寧な断りそのものから悲しい反応を作らない。回復は安堵として扱い、配慮に課題があるのに総合的には上がった場合は、その課題を無条件に褒めない。

好感度はゲーム内の関係の進行値。100でも交際成立を自動確定せず、結末は会話中の双方の意思と根拠を使う。未合格でも会話・分析・XPを保存し、6往復の専用イラストを獲得できる。演出は [リアクション選択](../src/lib/affinity-reaction.ts)、ゲームの数値は [進行仕様](stage-affinity-progression.md) を参照する。

## どこまで確認されているか

場面方針・引用・再送・不確かな採点・旧履歴・好感度の境界等は自動テストで確認し、架空会話を使う実Jev・Difyの生成確認と、表示・保存のfixture検証を分けて記録する。研究知見を練習へ応用した設計であり、検証済みの心理尺度や実際の恋愛成果の予測としては扱わない。実利用での自然さ・難易度・継続性は、別途確かめて調整する対象。

方針を変える場合は、関連する場面方針・Jev基準・Difyプロンプト・検証例・この文書を揃える。文章への指示で守る部分と、プログラムで引用・数値・権限を検証する部分を区別し、生成品質が毎回保証されると表現しない。

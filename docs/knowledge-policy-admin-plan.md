# 管理画面から更新する評価方針とRAG

## 目的と選択

編集場所はKoi-Treの管理画面。Difyは会話・分析の生成、Jevは5観点の実評価に継続使用する。Koi-Treが公開された方針と関連知識を組み立て、両方へ同じ内容を渡す。公開後の方針更新にはアプリやDifyの再デプロイを要しない。

この変更はDB、管理者認証、Dify/Jevへの入力、公開手順にまたがるため、通常の設計・実装・検証・段階公開の順で進める。管理者にするGoogleアカウントは別途指定を受け、UIDの許可リストで制限する。一般利用者には権限を付けない。

## 編集・公開の体験

1. 管理画面で基本方針と知識文書を編集し、下書き保存する。
2. 知識文書にはタイトル・本文・適用する場面を設定する。
3. 架空のサンプル会話で、検索された資料、返答、Jev評価、分析・言い換えを確認する。通常の練習・好感度・XP・利用枠へは反映しない。
4. 保存済みの同じ下書きで確認が成功し、内容を確認した管理者が公開する。
5. 公開版を履歴に残す。旧公開版への復帰も管理画面から行う。

変更の競合はリビジョンで検出し、古い画面からの保存・公開で上書きしない。保存・確認・公開・復帰はそれぞれ処理中・成功・失敗を表示する。

## 毎回適用する方針と検索する知識

- 基本方針は検索結果によらず毎回含める。双方の意思、場面の目的、本人の事実・意図、根拠、不確実さ等を編集できる。
- 補助知識は場面と話題に合う文書の箇所を検索して加える。まずは場面タグと日本語の文字列を扱うBM25で実装し、埋め込みAPIや外部ベクトルDBを増やさない。検索方式の版も記録し、将来のベクトル検索追加に備える。
- 関連箇所がなくても基本方針は維持する。引用の原文照合、出力形式、本人アクセスの検証等は既存のアプリ側の検証を維持する。
- 文書数・文字数・取得件数・入力全体を制限し、方針の途中切り捨てや過大なモデル入力を防ぐ。

初期データは現行の評価・アドバイス方針と場面別の説明を使う。初期公開までは既存の動作を維持する。

## 同じ版で会話・採点する

- 公開した文書は不変の版として保存し、現在の公開版への参照を別に管理する。
- 練習開始時に公開版を固定する。同じ練習の3/6往復、再送、再開、無料再評価ではその版を使う。
- 各生成で使った版・検索方式・文書／箇所・文脈ハッシュを記録する。Jevが取得できなかった場合も、使った方針は保存する。
- 無料再評価は元の文脈を復元してJevだけを呼ぶ。有効評価の振り直し、過去の分析・クリア・好感度の再計算は行わない。
- 公開版を変更・復帰しても、開始済みの練習と過去の履歴は保持する。新しい練習から切り替える。
- 導入前の練習は既存方針として扱い、新しい方針へ黙って置き換えない。

## 保存・認証・境界

- 下書きと現在の公開版を管理する行、公開版の履歴、練習が使う公開版ID、生成に使った文脈情報を加算的migrationで追加する。
- 管理APIは全てFirebaseトークンを検証し、サーバー環境の管理者UID許可リストで認可する。画面やメールアドレスの自己申告は認可に使わない。
- API境界、公開操作、永続化、文書検索、Dify/Jev連携を役割ごとに分ける。秘密情報や利用者固有の会話を共有キャッシュに置かない。
- 購入・料金・利用枠・合格点の値はこの管理画面では変更しない。本番課金は停止を維持する。

## Difyへの反映

既存Workflowへ任意の方針入力を一度追加する。未指定は従来どおり、指定時は基本方針と取得した参考文書を区別して参照する。Workflowが入力を受け取ったことを返し、アプリが方針の文脈ハッシュを照合する。旧Workflowが方針を無視して成功扱いになることを防ぐ。

Difyだけで資料を検索すると、先に呼ぶJevと違う方針になり得る。検索はアプリで行い、同じ結果をJevとDifyへ渡す。Difyのナレッジ検索枠や新しいDifyアプリを使わず、管理画面から方針を更新できる構成にする。

## 検証と公開順

1. 管理者の401/403、下書き保存、保存競合、確認結果と公開対象の一致、公開・復帰・履歴の不変性を検証。
2. 日本語検索、場面の絞り込み、ヒットなし、取得上限、基本方針の維持を検証。
3. Dify/Jevの入力一致、誤った受領応答の拒否、3/6往復、再開・再送・無料再評価での版固定を検証。
4. 独立DBでmigration、再generateの差分なし、既存の回帰テスト、型・lint・ビルドを確認。管理画面をPCとスマホで操作する。
5. Difyの互換入力を先に検証・公開し、加算的migrationとアプリを対応させる。管理者UIDは指定された本人だけを設定する。
6. 本番では下書きと架空会話の確認から始め、公開した後の新しい練習に適用する。DBや履歴を削除する切り戻しは行わない。

参考：[Dify Knowledge Retrieval](https://docs.dify.ai/en/cloud/use-dify/nodes/knowledge-retrieval)、[Difyの料金・制限](https://www.dify.ai/pricing)。外部サービスの制限は調査時点の情報であり、数値をアプリの固定仕様にはしない。

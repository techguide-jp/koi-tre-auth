# 期限なしの購入枠の残高管理

人物別ルートパックの専用24枠と追加共通15枠は、支払いに応じて利用回数を記録し、TechGuide合同会社が提供するKoi-Treの練習だけに使える。期限やユーザー間の移転機能はない。販売開始時は、いずれも自家型の前払式支払手段に該当する前提で管理する。人物パックの本編利用権は購入した人物に紐づく。24枠を使い切った後も、購入した本編は利用できる。

Plusの60枠は支払い済みの月次期間末に失効し、繰越・延長がない。6か月以内の期限の取扱いに沿い、期限なし枠の集計から除く。無償の月10枠は台帳の `free` で区分する。各枠の種別と有効期限は利用者のマイページで確認できる。別の事業者でも利用できる形にする場合や、利用期限・移転・購入条件を変える場合は、資金決済法上の扱いを再確認する。[金融庁の制度概要](https://www.fsa.go.jp/news/27/sonota/20151214-2.html) · [関東財務局の案内](https://lfb.mof.go.jp/kantou/kinyuu/pagekthp00400036.html)

## 残高の確認

1. 本番のPostgreSQLに読み取り用の接続で入り、[残高集計SQL](../scripts/check-prepaid-balances.sql) を実行する。`route`、`topup`、`total` の3行を確認する。個人情報や会話本文は出力しない。
2. `unused_units` は有効な購入枠から消費確定済みの枠を引いた残高。生成中に予約した枠は提供が確定するまで残高に含める。`grants_to_check` に件数が出た場合は、商品ごとの発行条件を台帳と照合する。
3. `estimated_unused_yen` は商品税込額を全枠に割り当てて按分し、購入ごとに円未満を切り上げた管理上の見積額。ルートパックは本編利用権の分を分けず、1,480円全額を按分する。価格・付与枠を変える場合は、購入時点の商品条件で計算する。届出額に使う段階では商品別の換算方法を管轄の財務局に確認する。
4. 決済通知の失敗・再送待ちや未反映の支払いをStripeで照合し、反映または別記する。月次と3月末・9月末の基準日時点で集計を保存する。失効や紛争の復元があるため、現在の台帳から過去の基準日残高を推定して置き換えない。
5. 発行者全体で合算する。同じ会社が別サービスで対象となる有償ポイント・商品券・回数券を発行している場合は、その残高も加える。

関東財務局は、自家型の基準日未使用残高が初めて1,000万円を超えた場合、事後届出が必要と案内している。残高が基準に近づいた時点で、換算方法、基準日の翌日から2か月以内の届出、発行保証金の保全、利用者への表示を確認する。提供を終了する場合は、未使用枠の告知・払戻しについて、停止前に適用される手続を確認する。[関東財務局の手続案内](https://lfb.mof.go.jp/kantou/kinyuu/pagekthp00400036.html) · [資金決済法](https://laws.e-gov.go.jp/law/421AC0000000059)

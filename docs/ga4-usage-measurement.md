# GA4 利用状況の計測設計・実装計画

## 目的と現状

GA4 で、訪問した人数、ログインして利用した人数、1 回以上質問した人数を期間別に確認する。アプリ内の管理画面は追加しない。

2026-11-01 の確認では、本番の Firebase Analytics は初回ページビューを送信している。SPA のページ遷移に対応する明示的な計測はなく、ログイン画面の自動ポップアップ成功時には `login` が送られない。質問は別ドメインの Dify iframe 内で行われ、保存成功時の GA4 イベントはない。

## 指標

| 指標                     | GA4 イベント          | 集計                                            |
| ------------------------ | --------------------- | ----------------------------------------------- |
| アクセスした人           | `page_view`           | 総ユーザー数。未ログイン時はブラウザ単位        |
| ログインして利用した人   | `authenticated_visit` | 総ユーザー数。ログイン状態の復元も含む          |
| ログイン操作を完了した人 | `login`               | 総ユーザー数。自動ポップアップとボタンの両方    |
| 新規登録した人           | `sign_up`             | 総ユーザー数。Firebase の新規ユーザー判定に従う |
| 1 回以上質問した人       | `question_submitted`  | 総ユーザー数。DB に質問・回答が保存された成功分 |
| 質問回数                 | `question_submitted`  | イベント数                                      |

ログイン状態が継続する利用者がいるため、主要な利用ファネルには `login` ではなく `authenticated_visit` を使う。期間中のアクセスと質問は開いたファネルでも確認できるようにする。質問保存前の離脱、API エラー、上限超過は質問成功数に含めない。

## 実装方針

- 既存の Firebase Analytics を維持し、本番ドメインだけで送信する。初回の自動ページビューを止め、SvelteKit の遷移ごとに明示的に送る。GA4 側の履歴変更による自動ページビューも確認し、二重送信を防ぐ。
- Firebase UID の SHA-256 値を GA4 の User-ID に設定し、ログアウト時には解除する。メール、氏名、質問文、回答、認証トークンは GA4 に送らない。ページ URL は検索パラメーターとフラグメントを除く。
- ログイン処理を一つにまとめ、ログイン成功・新規登録の計測抜けとボタンの重複操作を防ぐ。
- アクセスキー発行時にブラウザの GA4 client ID と session ID を取得し、任意の署名付き計測情報としてアクセスキーに含める。既存の v1 アクセスキーを引き続き受け付ける。
- Dify からの保存成功後に、同じ client ID / User-ID で Measurement Protocol の `question_submitted` を送る。計測が無効なブラウザには別の ID を生成しない。
- GA4 送信の失敗が質問保存の成功を取り消さないようにする。タイムアウトを設け、API シークレットをログやブラウザへ出さない。
- DB スキーマは変更しない。過去の質問を新しいイベントとして送信しない。
- GA4 Admin 用 CLI と README に、プロパティ確認、キーイベント設定、計測検証、GA4 の探索での見方を残す。

## 手順と検証

1. 本番の GA4 プロパティとストリームを特定し、API と閲覧・編集権限を確認する。
2. クライアント側のページビュー、User-ID、ログイン・ログイン利用の計測を実装する。
3. 署名付き計測情報と保存成功後のサーバーイベントを実装する。
4. 旧キーの互換性、改ざん拒否、保存失敗時の非送信、個人情報の非送信、計測失敗時の保存成功をテストする。
5. 型チェック・lint・テスト・ビルドを行い、ブラウザの collect リクエストと Measurement Protocol の検証結果を確認する。
6. 対象 GA4 のキーイベントと Vercel のサーバー設定を揃える。実施できた設定と権限不足で未実施の設定を区別して記録する。

## 過去データと制限

GA4 には過去の未計測ログイン・質問を復元できない。Neon の保存履歴は別の記録として扱う。広告ブロック、Cookie 削除、複数端末、GA4 のレポート反映遅延により、GA4 の人数と Firebase / Neon の件数は必ずしも一致しない。
